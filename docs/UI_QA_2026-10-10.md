# BuildProof frontend QA — 10 October 2026

## Scope

Authentication, three-step onboarding, the workspace shell, dashboard, search, record drawers, settings and the existing project suites. This is a UI rebuild in the existing Next.js repository, not a new hosted site. Sites' local-workflow guidance informed implementation and previewing; Humanizer informed the plain-language copy pass.

## Corrections

- Replaced eight overlapping imported redesign stylesheets with foundations, resilience styles and one product stylesheet. Legacy files remain available but are no longer imported.
- Rebuilt the visual hierarchy around white surfaces, light blue information panels, light orange selection states and high-contrast orange actions.
- Corrected invisible authentication content when reduced motion was enabled.
- Prevented Continue from accidentally launching onboarding when the step changed. Reserved validation space so errors cannot move buttons during mouse clicks.
- Added a real searchable project/module dialog, keyboard-accessible project menus, record drawers and a mobile navigation focus loop with Escape and focus restoration.
- Kept the sidebar and its navigation scroll separate from the workspace. Collapsed navigation retains accessible labels.
- Made sorting apply to all filtered records before pagination, preserved stable record selection IDs and made numeric columns sort numerically.
- Removed invented batch references, approval-like audit statuses, assumed author names and fixed map coordinates. The map remains explicitly illustrative; it is not a surveyed boundary or live mapping integration.
- Protected asynchronous dashboard loads from stale responses, surfaced failed queries and reset missing site locations when switching projects.
- Production testing found that static public pages had no script nonce despite a strict per-request CSP. The root now waits for a request before rendering, as required by the bundled Next.js CSP guide. Public pages therefore render dynamically rather than using static HTML/CDN caching.

## Reproduction

Start `npm run dev`, then run `npm run qa:ui`. Chromium must be installed for Playwright (`npx playwright install chromium`). Public Supabase configuration is read from `.env.local`; credentials are not printed.

The runner creates a temporary development-only page importing the real components. All Supabase HTTP requests are intercepted with fictional data, and the temporary route is removed in `finally`. It refuses remote origins and refuses to overwrite an existing harness route. Screenshots and the detailed report are under `test-results/ui`, ignored by Git.

The suite checks five widths (320, 360, 768, 1280 and 1536), Axe WCAG 2 A/AA rules, horizontal overflow, invisible headings, JavaScript exceptions, reduced motion and ordinary motion, email/OTP error UI, all module destinations and their forms, record drawers, global multi-page sorting, sidebar positioning, mobile menu dismissal, onboarding validation and invitation list controls. A regression assertion verifies that no onboarding RPC is called before Launch is clicked.

`npm run verify:release` additionally checks environment variable names, lint, TypeScript, production compilation, the repository secret scan and production dependency advisories.

`npm run qa:public` targets a local production server on port 3001. It proves authentication hydration by switching to sign-up, checks 320/1536 layouts, captures CSP violations, verifies anonymous workspace/onboarding redirects and confirms the fixture route is absent. These checks passed after the nonce rendering fix. The final health assertion remains red on this machine because `NEXT_PUBLIC_APP_URL` is missing; the endpoint correctly returns 503. Neither deployment configuration nor local environment files were changed to conceal that failure.

## Boundaries and remaining warnings

Passing UI fixtures does not prove real email delivery, Google/Microsoft OAuth, live organization creation, invitation acceptance, production persistence, cross-tenant permissions or industry readiness. Those need an authorized live-account end-to-end run. No account or production project records were changed by this QA.

Automated accessibility checks do not establish complete WCAG conformance. Screen-reader testing and construction-team usability feedback remain necessary.

The local environment lacks `NEXT_PUBLIC_APP_URL`; development callbacks fall back to the current origin. Verify the intended deployed origin in deployment configuration.

Lint reports three React Compiler/library compatibility warnings and two existing warnings in an unrelated pipeline utility. Production dependency audit reports no vulnerabilities. The full audit reports five high-severity development-tool findings in the ESLint/fast-glob/micromatch/braces chain. The registry still offers braces 3.0.3; the suggested automatic resolution downgrades Next's lint configuration to 14, so it was not applied to a Next 16 application.
